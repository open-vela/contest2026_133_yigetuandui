## 一、如何连接"手表"（黄山派开发板）

黄山派本身就是智能手表原型机，**只需要一根 USB Type-C 数据线**连到电脑：

1. **物理连接**：Type-C 线插板子上的 **Type-C（UART）口**——这个口板载 CH340N 芯片，一根线同时完成供电 + 串口控制台 + 程序烧录。
2. **装驱动**（仅 Windows 首次）：到沁恒官网下载 CH341SER 驱动安装；装完后"设备管理器 → 端口"里出现 **USB-SERIAL CH340 (COMx)**，记住这个 COM 号。
3. **开串口控制台**：用 PuTTY / Tabby / 串口调试助手打开该 COM 口，**波特率必须设 1000000（1Mbps）**——不是常见的 115200，乱码就是波特率错了。
4. 板子还有一个贴心设计：CH340N 的 **RTS 引脚直连芯片复位脚**，烧录工具可以软件触发复位，**不用按任何按键**就能进烧录模式。

## 二、搭建编译环境（推荐 WSL2 Ubuntu，约 20 分钟）

openvela 官方构建在 Linux 下进行。Windows 11 上装 WSL2：

```powershell
wsl --install -d Ubuntu-22.04     # PowerShell 管理员执行，装完重启
```

WSL 内安装工具链（要求：arm-none-eabi-gcc ≥10.3、cmake ≥3.22、ninja ≥1.10、python3 ≥3.10）：

```bash
sudo apt update
sudo apt install -y gcc-arm-none-eabi cmake ninja-build python3 git
```

## 三、拉取 openvela 源码并集成 aura_hw

```bash
mkdir -p ~/vela && cd ~/vela
git clone -b dev-ai-contest-2026 https://github.com/open-vela/nuttx.git
mkdir -p vendor && git clone -b dev-ai-contest-2026 https://github.com/open-vela/vendor_sifli.git vendor/sifli

# 集成我们的应用（把项目里的 aura_hw 拷进来，Windows 文件在 WSL 里路径为
# /mnt/c/Users/notebook/Desktop/Aura-Space/hardware/aura_hw）
cp -r /mnt/c/Users/notebook/Desktop/Aura-Space/hardware/aura_hw apps/
echo 'source "$APPSDIR/aura_hw/Kconfig"' >> apps/Kconfig
```

⚠️ **分支必须都是 `dev-ai-contest-2026`**，trunk/dev 缺芯片层依赖编不过。

## 四、配置并编译

```bash
cd ~/vela
cmake -B cmake_out/lckfb_huangshan_pi -S "$PWD/nuttx" -GNinja \
  -DBOARD_CONFIG=../vendor/sifli/boards/sf32lb52/lckfb_huangshan_pi/configs/nsh \
  -DEXTRA_FLAGS="-Wno-cpp -Wno-deprecated-declarations"

# 打开配置界面，启用以下选项后保存：
./nuttx/tools/kconfig-frontends... # 或用 menuconfig 方式
```

`menuconfig` 中需要确认开启：

| 配置项 | 作用 |
|---|---|
| `EXAMPLES_AURA_HW` | 我们的应用（Application configuration → aura） |
| `CONFIG_I2C_DRIVER=y` | I2C 字符设备（IMU 用 `/dev/i2cN`） |
| `CONFIG_PWM=y` | PWM 字符设备（马达用 `/dev/pwmN`） |
| `CONFIG_LIBC_FLOATINGPOINT=y` | printf 支持 %f（调试输出需要） |
| `CONFIG_KVDB=y` | 可选，五维数据持久化；不开则降级写文件 |
| `EXAMPLES_AURA_HW_IMU_PATH` | 默认 `/dev/i2c1`（已按 vendor 板级源码核实：IMU 在 I2C2 总线） |
| `EXAMPLES_AURA_HW_PWM_PATH` | 默认 `/dev/pwm0`（马达引脚待按立创原理图补 pinmux） |

编译：

```bash
cmake --build cmake_out/lckfb_huangshan_pi
# 产物：cmake_out/lckfb_huangshan_pi/nuttx.bin（约 1.5MB）
```

## 五、烧录（sftool，支持 Windows 直接烧）

1. 从 https://github.com/OpenSiFli/sftool/releases 下载 **sftool-0.2.5-x86_64-pc-windows-msvc.zip** 解压（Windows 可直接用，烧录不必在 WSL 里做）。
2. 板子 Type-C 连电脑，记下 COM 号（假设 COM5），Windows CMD 执行：

```bat
sftool -c SF32LB52 -p COM5 -b 1000000 --before default_reset --after soft_reset write_flash nuttx.bin@0x12010000
```

（WSL/Linux 下则把 `-p COM5` 换成 `-p /dev/ttyUSB0`，且需 `sudo usermod -aG dialout $USER` 后重新登录。）

3. 烧完自动软复位进 NSH，串口控制台出现 `nsh>` 提示符。

## 六、NSH 调测顺序（每步对应一条验收标准）

```bash
nsh> aura imu        # ① 甩腕看 gyro 数值变化；确认 WHO_AM_I=0x6a 初始化成功
nsh> aura vib 1      # ② 依次试 1~5，感受五种振动模式
nsh> aura gesture    # ③ 打印手势事件和置信度；每 10s 打印采样抖动
                     #    （目标：均值 <500us，最大 <2000us）
nsh> aura inject     # ④ 100 组注入波形准确率（目标 ≥90%，模拟器也可跑）
nsh> aura demo       # ⑤ 全链路：IMU→手势→判定→振动→五维存储
```

## 七、常见问题排查

| 现象 | 原因与处理 |
|---|---|
| 串口全是乱码 | 波特率错了，必须 1000000 |
| `[lsm6ds3] WHO_AM_I=0x00` | 已确认 IMU 在 I2C2=`/dev/i2c1`（Kconfig 默认已改对）；若仍失败，检查与内核 `lsm6dsl` 驱动是否被其他程序同时打开 |
| `aura vib` 无振动 | **预期内**：马达引脚 vendor 树未配置（见 README 已知待办 #3），需按立创原理图补 pinmux |
| 浮点数打印异常 | 没开 `CONFIG_LIBC_FLOATINGPOINT` |
| 手势全识别不出来 | 先用 `aura imu` 确认数据活着；阈值按真机波形标定（`gesture_recognizer.c` 顶部宏） |
| `[imu] I2C 连续失败，降级到 100Hz` | 故障降级机制在工作，检查排线/总线冲突 |

## 八、真机标定建议（W2~W3 的活）

1. `aura gesture` 模式下做 20 次每种手势，记录打印的置信度分布；
2. 若漏识别多 → 调低 `THRESH_*` 宏；误触发多 → 调高或收紧 `DOMINANT_RATIO`；
3. 调完用 `aura inject` + 真机各跑一轮回归。

## 附录 A：首次构建踩坑记录（复现构建必读）

以下问题在本次（2026-09-20）首次构建中全部实际遇到并解决，按出现顺序列出。
网络环境：github.com 被墙，api.github.com / codeload.github.com / gitee.com 可用。

### A1. 源码获取（github.com 不可用时）

- 三个仓库用 codeload 或 gitee 拉分支快照即可（无需 git 历史）：
  - `codeload.github.com/open-vela/{nuttx,vendor_sifli,nuttx-apps}/tar.gz/refs/heads/dev-ai-contest-2026`
  - gitee 镜像同路径下载更快（约 2 倍）
- ARM 工具链：developer.arm.com 可直接下载 arm-gnu-toolchain-12.3.rel1（Ubuntu apt 装的 10.3 亦可）
- pip 依赖（用阿里云镜像）：`pip install -i https://mirrors.aliyun.com/pypi/simple/ kconfiglib pyelftools cxxfilt`
- genromfs（board romfs 生成工具）：codeload 拉 chexum/genromfs 源码，`gcc -DVERSION=\"0.5.7\"` 编译后放入 PATH

### A2. FetchContent 网络失败（逐个预置源码）

cmake 配置阶段会从 github 拉取以下组件，全部失败，需预置到各自 SOURCE_DIR
（目录已存在则跳过下载；含 PATCH_COMMAND 的要手动打补丁）：

| 组件 | 版本 | 预置位置 | 备注 |
|---|---|---|---|
| libcxx | 17.0.6（API 资产 ID 查 LLVM release） | nuttx/libs/libxx/libcxx/libcxx | 5 个补丁全打（mbstate_t.patch 用 -p3） |
| LVGL | v9.2.1（codeload） | apps/graphics/lvgl/lvgl | 需两处源码补丁，见 A3 |
| quickjs | **2020-11-08**（bellard.org，勿用 master，master 没有 libbf.c） | apps/interpreters/quickjs/quickjs | 补丁 hunk3 失败时手动注释 os.exec |
| cJSON | v1.7.12 | apps/netutils/cjson/cJSON | 注意防止嵌套目录 |
| libuv | v1.46.0（随首次 configure 自动成功过） | apps/system/libuv/libuv | 需 1 处源码补丁，见 A3 |

⚠️ 高频坑：预置解压时若目标目录已被失败构建创建（空壳），`mv` 会造成
**嵌套目录**（如 cJSON/cJSON-1.7.12/…），打补丁前务必确认目录结构。

### A3. 必需的源码补丁（均已提交在 WSL 构建树，重拉源码需重打）

1. `apps/graphics/lvgl/CMakeLists.txt`：`add_subdirectory(lvgl/tests/cmake_nuttx)`
   加 `if(EXISTS ...)` 保护（官方 v9.2.1 无此目录）
2. `apps/graphics/lvgl/lvgl/src/drivers/nuttx/lv_nuttx_entry.c`（上游 9.2.1 三处 bug）：
   - 补 `#include <uv.h>`（CONFIG_LV_USE_NUTTX_LIBUV 分支）
   - 调用处 `lv_nuttx_uv_loop(&ui_loop, result)` → `lv_nuttx_uv_loop(result)`
   - `uv_run(loop, ...)` → `uv_run(&loop, ...)`
3. `apps/system/libuv/libuv/src/unix/loop.c`：`uv__process_init(loop)` 调用
   加 `#ifndef __NuttX__` 保护（process-spawn.c 仅在 CONFIG_LIBC_EXECFUNCS 下编译）
4. `apps/graphics/lvgl/lvgl/src/lv_conf_internal.h`：
   `LV_ATTRIBUTE_LARGE_CONST` 定义改为空（kconfig 空字符串默认值的引号会破坏语法）
5. `apps/graphics/lvgl/lvgl/src/drivers/nuttx/lv_nuttx_image_cache.c`：
   `gettid()` → `getpid()`（NuttX 无 gettid，此处仅用于堆命名）
6. `nuttx/libs/libxx/libcxx/libcxx/include/__locale`：
   删除全部 `_LIBCPP_SUPPRESS_DEPRECATED_PUSH/POP` 行（GCC 12 解析问题，
   且全局已有 -Wno-deprecated-declarations，语义无影响）
7. `nuttx/libs/libxx/libcxx/libcxx/include/__mbstate_t.h`：
   `#include_next <wchar.h>` → `#include <wchar.h>`（走 libcxx 自己的 wchar.h 包装）
8. `EXTRA_FLAGS` 追加 `-fpermissive`（libcxx 与 GCC 12 的模板查找兼容）

### A4. defconfig 需要追加/修改的项

```
CONFIG_I2C_DRIVER=y            # IMU 用 /dev/i2cN（本板默认已开）
CONFIG_LIBC_FLOATINGPOINT=y    # printf %f
CONFIG_LIBC_WCHAR=y
CONFIG_CXX=y
CONFIG_CXX_WCHAR=y             # 关键：否则 libcxx 定义 _LIBCPP_HAS_NO_WIDE_CHARACTERS → mbstate_t 报错
CONFIG_EXAMPLES_AURA_HW=y
# CONFIG_LV_USE_FREETYPE is not set   # freetype 源码树缺失，先关闭
# CONFIG_LV_USE_LIBPNG is not set     # libpng 源码树缺失，先关闭
```

### A5. 集成 aura_hw 的关键认知

- **cmake 构建不认根 apps/Kconfig**：应用被发现依赖 `apps/CMakeLists.txt` 的
  `add_subdirectory(aura_hw)` + 本目录 `aura_hw/CMakeLists.txt`
  （`nuttx_add_application(...)`）。Makefile/Make.defs 仅服务 legacy make 构建。
- **改 defconfig 后必须全新配置**：cmake 缓存不会重读 defconfig，
  把 `cmake_out` 目录改名移走再跑配置脚本（直接删除也行）。
- **本分支 i2c ioctl 命令码是 `I2CIOC_TRANSFER`**（不是 `I2C_TRANSFER`，
  后者是内核侧函数宏）；`i2c_msg_s` 为带 `frequency` 字段的旧版布局。
- NSH 平坦地址空间下，文件静态变量跨命令残留：服务启动必须显式复位
  滤波/时钟状态（已在 imu_service.c 的 imu_state_reset() 处理）。
